# Руководство для контрибьюторов Mr.Comic

Приветствуем вас в проекте Mr.Comic! Мы рады любой помощи в развитии лучшего приложения для чтения комиксов на Android.

Этот документ описывает процесс внесения вклада в проект.

## 🛠 Технологический стек

Проект является нативным Android-приложением. Пожалуйста, убедитесь, что вы знакомы со следующими технологиями:

*   **Язык**: Kotlin
*   **UI**: Jetpack Compose (Material 3)
*   **Архитектура**: Clean Architecture + MVVM (Multi-module)
*   **DI**: Hilt
*   **Асинхронность**: Coroutines & Flow
*   **БД**: Room
*   **Сборка**: Gradle (Kotlin DSL)

## 🚀 Подготовка окружения

1.  **Android Studio**: Используйте последнюю стабильную версию.
2.  **JDK**: Проект использует Java 17.
3.  **Android SDK**: Убедитесь, что установлены SDK Platform 34 и Build-Tools.

### Сборка проекта

```bash
# Клонирование репозитория
git clone https://github.com/your-username/Mr.Comic.git

# Переход в папку проекта
cd Mr.Comic

# Сборка Debug версии
./gradlew assembleDebug
```

## 🐛 Сообщение об ошибках (Bug Reports)

При создании Issue с багом, пожалуйста, указывайте:
1.  **Версию приложения** (или коммит).
2.  **Модель устройства** и версию Android.
3.  **Шаги воспроизведения**.
4.  **Ожидаемое и фактическое поведение**.
5.  Приложите **скриншоты** или запись экрана, если проблема визуальная.
6.  Приложите **Logcat** (стек-трейс), если приложение падает.

## ✨ Предложение улучшений (Feature Requests)

Если у вас есть идея новой функции:
1.  Проверьте, нет ли уже такой задачи в `ROADMAP.md` или в Issues.
2.  Создайте Issue с типом `enhancement`.
3.  Опишите, какую проблему решает функция и как она должна работать.

## 💻 Процесс разработки (Pull Requests)

1.  **Форкните** репозиторий.
2.  Создайте ветку для вашей задачи:
    *   `feature/название-фичи` — для новых функций.
    *   `fix/название-бага` — для исправлений.
    *   `refactor/что-улучшаем` — для рефакторинга.
3.  Вносите изменения, следуя **Code Style**.
4.  Запустите тесты перед отправкой:
    ```bash
    ./gradlew testDebugUnitTest
    ```
5.  Создайте Pull Request (PR) в ветку `main`.
6.  В описании PR укажите ссылки на связанные Issues (например, `Fixes #123`).

### Стиль кода (Code Style)

*   Мы придерживаемся официального Kotlin Style Guide.
*   Используйте `ktlint` или встроенное форматирование Android Studio.
*   Имена классов, функций и переменных должны быть на английском языке и отражать суть.
*   UI-компоненты (Composables) должны быть именованы как существительные (например, `ComicCard`, а не `DrawComic`).
