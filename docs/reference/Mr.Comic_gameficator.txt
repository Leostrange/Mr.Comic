# Mr. Comic для Android

## 1. Что это в продукте

**Mr. Comic** — это живой персонаж внутри приложения, который:

* появляется в ключевых точках интерфейса,
* растёт вместе с пользователем,
* реагирует на чтение,
* не мешает чтению,
* усиливает удержание через эмоциональную связь.

На Android его лучше внедрять **не как постоянно болтающего помощника**, а как **легковесный UI-слой состояния прогресса**.

То есть:

* в ридере он почти незаметен,
* на главной — более живой,
* на экранах прогресса — выразительный,
* в пушах и виджетах — узнаваемый.

---

# 2. Как он должен выглядеть в мобильном приложении

Полноразмерный нуарный мужчина в плаще — сильный образ, но для Android UI его нужно **масштабировать до системы состояний**.

## В приложении у него должно быть 3 визуальных формата:

### A. Мини-аватар

Используется:

* на главной,
* в профиле,
* в карточке прогресса,
* в тулбаре событий.

Вид:

* бюст или силуэт по пояс,
* шляпа, воротник плаща, тень на глазах,
* минимальная анимация: дыхание, моргание, наклон головы.

### B. Сценовый персонаж

Используется:

* экран возвращения,
* экран роста,
* достижение новой стадии,
* экран “давно не читал”.

Вид:

* почти полный рост,
* дождь, неон, улица, отражения,
* кинематографичная подача.

### C. Эволюционные версии

Используется:

* для взросления.

Этапы:

1. **Comic Boy** — ребёнок
2. **Young Comic** — подросток
3. **Comic Detective** — юноша
4. **Mr. Comic** — взрослый

Для Android это важно, потому что не нужен один тяжёлый 3D-персонаж. Нужен **набор оптимизированных 2D/Live2D/Lottie-состояний**.

---

# 3. Как встроить в UX, чтобы не мешал чтению

## Главный принцип

Во время чтения пользователь пришёл читать, а не смотреть на маскота.

Поэтому:

### В ридере:

* Mr. Comic не перекрывает текст;
* находится в маленьком углу или вызывается по жесту;
* показывает только состояние, без навязчивых реплик;
* может исчезать при начале чтения и мягко появляться на паузе.

### Вне ридера:

* становится полноценным эмоциональным элементом.

# 4. Где он живёт в Android-приложении

## Экран Home

Здесь Mr. Comic — центральная точка возврата.

Что показывает:

* текущее настроение,
* прогресс до следующей стадии,
* реакцию на недавнее чтение.

Пример:
“Ты вернулся. Я ждал продолжения.”

Без длинных диалогов. 1 короткая фраза максимум.

---

## Экран Reader

Очень деликатно.

Вариант:

* маленькая иконка-силуэт внизу/сбоку,
* по тапу открывается карточка состояния:

  * настроение,
  * рост,
  * streak,
  * ближайшая эволюция.

---

## Экран Progress / Profile

Здесь раскрывается вся система:

* текущая стадия,
* сколько прочитано,
* история роста,
* визуальная шкала эволюции,
* архив образов.

---

## Экран Return

Если пользователь не заходил 2–4 дня:

* полноэкранная сцена с дождём,
* Mr. Comic стоит в неоне,
* короткая фраза,
* CTA: “Продолжить чтение”.

Это очень хорошо работает на Android как entry-screen после запуска.

# 5. Система взросления в мобильной логике

## Базовая модель

Персонаж растёт не “по донату”, не по валюте, а по чтению:

* страницы,
* минуты,
* завершённые главы,
* дни подряд,
* тип контента.

## Рекомендуемая модель очков

### Начисление

* 1 страница = 1 XP
* 1 минута чтения = 0.5 XP
* завершение главы = +15 XP
* завершение тома/книги = +60 XP
* серия дней = множитель или бонус

### Порог стадий

* Stage 1: 0–199 XP
* Stage 2: 200–699 XP
* Stage 3: 700–1599 XP
* Stage 4: 1600+ XP

На Android это удобно хранить локально и синкать с backend.

# 6. Состояния маскота

Нужно не 100 состояний, а понятный набор.

## Стадии

* CHILD
* TEEN
* YOUNG
* ADULT

## Настроение

* INSPIRED
* CALM
* TIRED
* LONELY

## Контекст

* READING
* WAITING
* RETURN
* LEVEL_UP
* IDLE

Итоговое состояние собирается из комбинации:
`stage + mood + context`

Пример:
`ADULT + LONELY + RETURN`

Это и определяет:

* какую анимацию показать,
* какой арт использовать,
* какую короткую реплику вывести.

# 7. Как описать внешний вид по стадиям для Android-ассетов

## Stage 1 — Comic Boy

* мальчик 6–8 лет,
* большая шляпа “на вырост”,
* слишком длинный маленький плащ,
* большие глаза,
* мягкий силуэт,
* чаще смотрит вверх,
* двигается чуть неуклюже.

UI-смысл: вызывает привязанность.

## Stage 2 — Young Comic

* 10–13 лет,
* черты становятся острее,
* плащ уже сидит лучше,
* появляется уверенность,
* он уже не просто милый, а любопытный наблюдатель.

## Stage 3 — Comic Detective

* 16–20 лет,
* почти сформированный нуарный стиль,
* меньше детской мягкости,
* появляется спокойствие и собранность,
* движения точнее.

## Stage 4 — Mr. Comic

* взрослый мужчина,
* вытянутый силуэт,
* fedora,
* тёмный плащ до колен,
* лицо частично в тени,
* редкие эмоции,
* тяжёлая атмосферность,
* сдержанная пластика.

# 9. Бизнес-логика состояния

## Обновление после чтения

```kotlin
fun updateMascotAfterReading(
    old: MascotState,
    pagesRead: Int,
    minutesRead: Int,
    chapterFinished: Boolean
): MascotState {
    var gainedXp = pagesRead + (minutesRead / 2)
    if (chapterFinished) gainedXp += 15

    val newXp = old.xp + gainedXp
    val newStage = calculateStage(newXp)

    return old.copy(
        xp = newXp,
        stage = newStage,
        mood = MascotMood.INSPIRED,
        totalPagesRead = old.totalPagesRead + pagesRead,
        totalMinutesRead = old.totalMinutesRead + minutesRead,
        lastReadAt = System.currentTimeMillis(),
        context = if (newStage != old.stage) MascotContext.LEVEL_UP else MascotContext.READING
    )
}
```

## Расчёт стадии

```kotlin
fun calculateStage(xp: Int): MascotStage {
    return when {
        xp < 200 -> MascotStage.CHILD
        xp < 700 -> MascotStage.TEEN
        xp < 1600 -> MascotStage.YOUNG
        else -> MascotStage.ADULT
    }
}
```

## Расчёт настроения

```kotlin
fun calculateMood(lastReadAt: Long): MascotMood {
    val diffHours = (System.currentTimeMillis() - lastReadAt) / (1000 * 60 * 60)

    return when {
        diffHours < 24 -> MascotMood.INSPIRED
        diffHours < 48 -> MascotMood.CALM
        diffHours < 96 -> MascotMood.TIRED
        else -> MascotMood.LONELY
    }
}
```

# 15. Как не испортить UX Android-приложения

Очень важно:

## Не надо

* постоянных всплывающих окон,
* говорящей головы на каждой странице,
* перекрытия текста,
* долгих forced-анимаций,
* чувства, что пользователь “должен кормить персонажа”.

## Надо

* короткие реакции,
* атмосферные сцены,
* редкие сильные появления,
* ощущение роста,
* уважение к читателю.

# Блок ТЗ: анимации для Mr. Comic

## 1. Общий принцип анимаций

Анимации Mr. Comic должны:

* усиливать эмоциональную связь,
* показывать состояние прогресса,
* не мешать чтению,
* быть короткими и читаемыми,
* работать плавно даже на средних Android-устройствах.

### Ограничения

* в ридере — только лёгкие микроанимации;
* длинные сценовые анимации — только вне ридера;
* одна анимация не должна блокировать основной пользовательский сценарий;
* все анимации должны иметь возможность пропуска или мягкого скрытия.

---

# 2. Форматы анимаций

## Для MVP

Использовать:

* **Lottie** — для loop/entry/reaction-анимаций,
* **PNG/WebP sequence** — для простых сцен, если нужно,
* **Compose animation / Android property animation** — для смещений, прозрачности, масштабирования.

## Для сцен повышенного качества

Допустимо:

* Rive
* Live2D

Но в MVP рекомендовано оставить:

* 2D персонаж,
* 2–4 слоя окружения,
* отдельные эффекты дождя/неона/тумана.

---

# 3. Категории анимаций

Нужно разделить анимации на 4 уровня:

## A. Idle-анимации

Показывают, что персонаж живой.

## B. Reaction-анимации

Реакция на действия пользователя.

## C. Transition-анимации

Переход между состояниями, экранами и стадиями.

## D. Scene-анимации

Редкие, эмоционально сильные события.

---

# 4. Набор обязательных анимаций для MVP

## 4.1 Idle-анимации

### 1. Idle Breathing

**Назначение:** базовое состояние персонажа.
**Где используется:** Home, Profile, Progress, Reader bubble.
**Описание:**

* лёгкое движение корпуса вверх-вниз;
* едва заметное движение плеч;
* плащ и воротник слегка смещаются;
* у взрослой формы — очень сдержанно.

**Длительность цикла:** 2.5–4 сек
**Loop:** бесконечный
**Интенсивность:** низкая

---

### 2. Blink

**Назначение:** оживление взгляда.
**Описание:**

* редкое моргание;
* у ребёнка чаще;
* у Mr. Comic реже и медленнее.

**Частота:** 1 раз в 4–8 сек случайно
**Длительность:** 200–400 мс

---

### 3. Head Tilt

**Назначение:** интерес / внимание.
**Описание:**

* лёгкий наклон головы;
* затем возврат в neutral.

**Длительность:** 600–900 мс
**Триггер:** открытие home, тап по карточке, завершение главы

---

## 4.2 Reaction-анимации

### 4. Reading Start Reaction

**Когда:** пользователь начал читать.
**Описание:**

* персонаж оживает;
* поднимает голову;
* свет/контур слегка усиливается;
* у ребёнка — заметная радость;
* у взрослого — лёгкий уверенный сдвиг корпуса.

**Длительность:** 800–1200 мс

---

### 5. Reading Progress Reaction

**Когда:** каждые N страниц или по завершении главы.
**Описание:**

* короткая позитивная реакция;
* ребёнок: оживляется, делает небольшой шаг/жест;
* подросток: поправляет плащ/осматривается;
* взрослый: лёгкий кивок, полуоборот, усиление неона.

**Длительность:** 700–1000 мс
**Частота:** не чаще 1 раза за 3–5 минут чтения

---

### 6. Return Reaction

**Когда:** пользователь вернулся после перерыва.
**Описание:**

* персонаж сначала в более статичном состоянии;
* затем поднимает голову;
* делает один шаг вперёд или слегка разворачивается;
* свет усиливается.

**Длительность:** 1.2–2 сек
**Тип:** ключевая эмоциональная анимация

---

### 7. Sad / Lonely Reaction

**Когда:** пользователь не читал 3–4+ дня.
**Описание:**

* персонаж неподвижен;
* голова слегка опущена;
* плащ тяжелее “висит”;
* дождь становится заметнее;
* неон приглушён.

**Длительность:** loop-состояние
**Интенсивность:** низкая, без чрезмерной драматизации

---

## 4.3 Transition-анимации

### 8. Stage Up Transition

**Когда:** переход на новую стадию взросления.
**Описание:**

* затемнение фона;
* вокруг персонажа появляется световой контур;
* silhouette morph / плавная смена формы;
* меняются пропорции, одежда, поза;
* финал — новая стадия в hero pose.

**Длительность:** 2–3.5 сек
**Важность:** высокая
**Пропуск:** да, по тапу

---

### 9. Mood Change Transition

**Когда:** меняется настроение.
**Описание:**

* меняется свет, поза и микромимика;
* без отдельной длинной сцены;
* переход должен быть почти незаметным.

**Длительность:** 400–700 мс

---

### 10. Appear / Disappear

**Когда:** вход/выход персонажа из UI.
**Описание:**

* fade + лёгкий vertical offset;
* для нуарного персонажа можно добавлять проявление из тени;
* для ребёнка — более мягкое всплытие.

**Длительность:** 250–500 мс

---

## 4.4 Scene-анимации

### 11. Rain Scene

**Когда:** long absence / return / home-state lonely
**Описание:**

* персонаж стоит под дождём;
* на фоне неоновые вывески;
* на мокром асфальте отражения;
* персонаж почти неподвижен, только плащ, дождь и дыхание.

**Длительность:** 4–8 сек loop
**Где:** экран возврата, home-state

---

### 12. First Appearance Scene

**Когда:** первый запуск.
**Описание:**

* тёмный фон;
* маленькая светящаяся фигура/ребёнок проявляется;
* он делает первый осознанный взгляд на пользователя;
* после этого UI открывается.

**Длительность:** 2–4 сек
**Пропуск:** да

---

### 13. Book Completion Scene

**Когда:** пользователь завершил книгу/том.
**Описание:**

* персонаж выходит на передний план;
* свет усиливается;
* поза становится уверенной;
* возможно появление дождя, который сменяется чистым неоном;
* короткий triumph-момент.

**Длительность:** 1.5–2.5 сек

## Микроанимации

* 200–900 мс

## Обычные реактивные

* 700–1500 мс

## Переходы стадии

* до 3.5 сек

## Сценовые

* до 8 сек loop
* если one-shot, лучше до 4 сек

### Ограничение UX

* анимация не должна удерживать пользователя без необходимости;
* все большие сцены должны иметь кнопку skip или прерываться по тапу.

# 8. Производительность на Android

## Требования

* 60 fps на современных устройствах;
* допустимо 30 fps на слабых устройствах в сценовых анимациях;
* никакой тяжёлой realtime-3D графики для ридера;
* не более 1 одновременно активной сложной анимации на экране чтения.

## Оптимизация

* ассеты разбить по stage/state;
* тяжёлые rain/neon эффекты вынести отдельными слоями;
* использовать lazy-loading;
* preload только текущую и следующую часто используемую анимацию;
* для слабых устройств предусмотреть reduced motion mode.

---

# 9. Reduced Motion режим

Нужно предусмотреть упрощённый режим анимаций для:

* слабых устройств,
* пользователей с системным уменьшением анимаций,
* энергосбережения.

## В reduced mode:

* убрать сложный дождь,
* заменить сценовые анимации на fade + swap,
* сократить амплитуду idle,
* отключить второстепенные эффекты неона/частиц.

# 14. Логика выбора анимации

Пример для Android-логики:

```kotlin
fun resolveMascotAnimation(
    stage: MascotStage,
    mood: MascotMood,
    context: MascotContext
): String {
    return when {
        context == MascotContext.LEVEL_UP && stage == MascotStage.TEEN ->
            "scene_stageup_child_to_teen"

        context == MascotContext.LEVEL_UP && stage == MascotStage.YOUNG ->
            "scene_stageup_teen_to_young"

        context == MascotContext.LEVEL_UP && stage == MascotStage.ADULT ->
            "scene_stageup_young_to_adult"

        context == MascotContext.RETURN && mood == MascotMood.LONELY ->
            "mascot_${stage.name.lowercase()}_return_reaction"

        mood == MascotMood.LONELY ->
            "mascot_${stage.name.lowercase()}_lonely_loop"

        context == MascotContext.READING ->
            "mascot_${stage.name.lowercase()}_reading_reaction"

        else ->
            "mascot_${stage.name.lowercase()}_idle"
    }
}
```

# 15. Короткое требование для художника и аниматора

Анимации Mr. Comic должны передавать взросление через изменение пластики:

* ребёнок — эмоциональный и открытый,
* подросток — любопытный,
* юноша — собранный,
* взрослый — сдержанный и кинематографичный.

У взрослой стадии акцент переносится:

* с мимики на позу,
* с резкого движения на паузу,
* с тела на силуэт, свет, дождь и ткань плаща.

# 16. Что обязательно добавить в итоговое ТЗ одной фразой

**Все анимации Mr. Comic должны быть state-driven, вызываться событиями чтения и не препятствовать основному пользовательскому действию — чтению контента.**

Понял. Тогда **полностью сужаем ТЗ**:
маскот **анимируется только на двух экранах**:

* **Continue**
* **Library**

На всех остальных экранах маскот либо отсутствует, либо статичен без анимаций.

Ниже — переделанная версия ТЗ.

---

# ТЗ: анимации маскота Mr. Comic только для экранов Continue и Library

## 1. Область применения

Анимации маскота **Mr. Comic** используются **только** на следующих экранах приложения:

* **Continue**
* **Library**

На экранах:

* Reader
* Translation / OCR
* Settings
* Onboarding
* App Icon Settings
* Crash Report
* Video Splash

анимации маскота **не используются**.

---

## 2. Главная цель

Маскот должен:

* усиливать эмоциональную связь с прогрессом чтения;
* поддерживать сценарий “вернуться и продолжить”;
* не мешать работе с библиотекой;
* быть атмосферным, но ненавязчивым;
* не создавать лишнюю нагрузку на UI.

---

# 3. Экран Continue

## 3.1 Роль маскота на экране

Экран **Continue** — это **главный экран маскота**.

Именно здесь:

* показывается текущее состояние персонажа;
* считывается настроение;
* отражается чтение и перерывы;
* проигрываются основные реакции;
* пользователь эмоционально связывает прогресс чтения с Mr. Comic.

---

## 3.2 Контейнер размещения

Маскот размещается **внутри companion-card**.

Позиция:

* после checkpoint trail
* перед empty state / Continue reading / Currently reading

---

## 3.3 Разрешённые анимации на Continue

### Базовые

* `idle_breathing`
* `blink`
* `head_tilt`

### Реактивные

* `return_reaction`
* `resume_reading_focus`
* `checkpoint_memory_ack`
* `reading_progress_reaction`
* `continue_cta_reaction`

### Состояния

* `lonely_idle`
* `inspired_idle`
* `calm_idle`

### Сценовые

* `stage_up_preview`
* `completion_tease` *(опционально, если нужно связать завершение книги с Continue)*

---

## 3.4 Когда запускать анимации на Continue

### При первом открытии экрана

Запускать:

* `return_reaction`, если пользователь вернулся после перерыва;
* иначе `idle_breathing`.

### Если есть карточка Continue reading

Можно запускать:

* `resume_reading_focus`

### Если есть Currently reading

Можно запускать:

* `reading_progress_reaction`

### Если показан empty state

Запускать:

* `lonely_idle` или `calm_idle`

### Если пользователь тапнул по checkpoint trail

Запускать:

* `checkpoint_memory_ack`

### Если изменился stage персонажа

Запускать:

* `stage_up_preview`

---

## 3.5 Что запрещено на Continue

* полноэкранные длинные кат-сцены;
* перекрытие trail;
* перекрытие большой карточки Continue reading;
* постоянные активные движения;
* зацикленные тяжёлые эффекты дождя/неона;
* повторяющиеся реакции при каждом recomposition.

---

## 3.6 Частотные ограничения на Continue

* не более **1 заметной реактивной анимации** при открытии экрана;
* повторная реакция не раньше чем через **8–12 секунд** без нового события;
* idle-анимация должна быть спокойной и цикличной.

---

# 4. Экран Library

## 4.1 Роль маскота на экране

На экране **Library** маскот играет **второстепенную роль**.

Он не должен быть центром внимания. Его задача:

* мягко сопровождать пользователя;
* реагировать на пополнение библиотеки;
* поддерживать атмосферу;
* оживлять пустые состояния.

---

## 4.2 Контейнер размещения

Маскот размещается:

* в верхней части экрана как компактный embedded-блок,
  или
* в отдельной небольшой companion-area над контентом библиотеки.

Важно:

* не внутри списка;
* не поверх grid/list;
* не внутри карточек книг/папок.

---

## 4.3 Разрешённые анимации на Library

### Базовые

* `idle_breathing_light`
* `blink`

### Реактивные

* `library_open_reaction`
* `collection_growth_reaction`
* `quote_jump_ack`
* `bookmark_section_ack`

### Состояния

* `empty_library_idle`
* `calm_idle`

---

## 4.4 Поведение по секциям Library

### Files

Разрешены:

* `idle_breathing_light`
* `library_open_reaction`
* `collection_growth_reaction`

Триггеры:

* вход на экран;
* добавление файла;
* добавление папки;
* успешное обновление библиотеки.

---

### Bookmarks

Разрешены:

* `bookmark_section_ack`
* `calm_idle`

Если секция пустая:

* `empty_library_idle`

---

### Quotes

Разрешены:

* `quote_jump_ack`
* `calm_idle`

Если пользователь нажал на quote-card и выполняется переход в reader:

* короткий `quote_jump_ack`

Если источник недоступен и показывается snackbar:

* маскот не анимируется дополнительно.

---

## 4.5 Что запрещено на Library

* крупные сценовые анимации;
* реакции при каждом скролле;
* перекрытие filter/menu/breadcrumbs;
* анимации в зоне list/grid;
* длинные вступительные эффекты;
* конфликт с long-press карточек и папок.

---

## 4.6 Частотные ограничения на Library

* не более **1 заметной реакции** на вход в экран;
* при скролле — только idle или полная заморозка;
* реакция на добавление файла/папки должна быть короткой, до **1 секунды**.

# 11. Acceptance Criteria

Система считается готовой, если:

1. Маскот анимируется **только** на экранах Continue и Library.
2. На Continue маскот встроен в companion-card.
3. На Continue корректно работают idle, return, progress, lonely и checkpoint-реакции.
4. На Library маскот не мешает grid/list, filters, breadcrumbs и long-press.
5. На Files, Bookmarks и Quotes реакции различаются по контексту.
6. На пустых состояниях Continue и Library маскот показывает спокойное или lonely-состояние.
7. При скролле Library маскот не создаёт визуального шума.
8. Ни один другой экран приложения не запускает анимации маскота.

# 12. Главное правило

**Mr. Comic — активный эмоциональный элемент только на Continue и мягкий фоновый спутник на Library.**

Если хочешь, я следующим сообщением соберу это в **совсем рабочий табличный формат для команды**:
**экран | контейнер | анимации | триггеры | запреты | приоритет**.
