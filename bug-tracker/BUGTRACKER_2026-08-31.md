## P0 — общие проблемы Reader

### BUG-CORE-01 — восстановление позиции чтения
При повторном открытии книги фактическая позиция должна совпадать с сохранённой. Проверить выход в библиотеку и возврат, перезапуск приложения, смену режима чтения и восстановление позиции после repagination.

### BUG-CORE-02 — неверный расчёт количества страниц
`totalPages` и текущая страница могут не соответствовать реальному документу. Нельзя считать страницу только по промежуточному состоянию WebView/reflow. Проверить начало, середину и реальный конец книги.

### BUG-CORE-03 — ложные 100% прогресса
Прогресс не должен становиться 100%, пока пользователь физически не достиг конца документа. Slider, `currentPage / totalPages`, сохранённый прогресс и карточка библиотеки должны использовать согласованную модель.

### BUG-CORE-04 — paged reflow / фрагментация текста
В постраничном режиме проверить разбиение текста на страницы, переносы, высоту viewport, CSS columns/pagination и влияние chrome/insets. Не допускать пропусков, дублирования и некорректных границ страниц.

### BUG-CORE-05 — смена Pages ↔ Vertical
Переключение режима не должно сбрасывать книгу в начало/конец, менять тему или ломать прогресс. Позиция должна переводиться между режимами максимально близко к тому же месту текста.

## Форматы

### BUG-EPUB-01 — EPUB: позиция, пагинация и прогресс
Проверить EPUB как эталонный reflowable-формат: открытие, `Pages`, `Vertical`, переключение между ними, возврат из библиотеки, текущую/общую страницу, slider, 100% только в конце, TOC/внутренние ссылки и сноски.

### BUG-MOBI-01 — MOBI: сноска не оформляется как ссылка
В MOBI номер сноски визуально не выделяется как кликабельная ссылка (на тестовом файле `[1]` не имеет ожидаемого синего/link-оформления). Проверить сохранение anchor/link-разметки при парсинге MOBI и HTML/CSS ридера. Сноска должна быть визуально различима и открываться корректно.

### BUG-FB2-01 — FB2: структура и навигация
Проверить заголовки/секции, внутренние ссылки и сноски, восстановление позиции, Pages/Vertical и корректный прогресс. Исправления не должны ломать front matter.

### BUG-TXT-01 — TXT в архиве: метаданные/структура и отображение
На том же тестовом пакете TXT-вариант отображает содержимое иначе, чем MOBI. Проверить извлечение TXT из архива, кодировку, отделение метаданных/front matter от основного текста, абзацы и отсутствие искусственного склеивания структуры.

### BUG-RTF-01 — RTF: неверный page/progress state
Для RTF наблюдается некорректное состояние счётчика/прогресса (на тестовом примере интерфейс показывает `2 / 2` и `100%`, хотя фактическое чтение/позиция не соответствует реальному окончанию документа). Проверить преобразование RTF → reflowable content и интеграцию с общей системой pagination/progress.

### BUG-DOCX-01 — DOCX: документ превращается в одну длинную вертикальную полосу
DOCX отображается как чрезвычайно длинное вертикальное полотно/страница и не преобразуется в нормальную горизонтальную постраничную раскладку в режиме `Pages`. Скриншоты были склеены только для демонстрации масштаба проблемы. Проверить DOCX → HTML pipeline, CSS paged layout, размеры root/body, column layout и viewport geometry.

### BUG-MD-01 — Markdown: проверить общий reflow pipeline
Markdown должен проходить ту же матрицу Pages/Vertical, restore/progress и внутренние ссылки. Не вводить отдельный форматный костыль, если причина находится в общем HTML Reader pipeline.

## Reader UI

### BUG-UI-CHROME-01 — Chrome-панели перекрывают контент
В landscape/широком режиме панели управления занимают слишком большую часть экрана и закрывают страницу. Ориентир — компактные полупрозрачные верхняя/нижняя панели поверх контента, при которых книга остаётся видимой. Не удалять существующие функции и кнопки: требуется компактная адаптивная компоновка.

### BUG-UI-CROP-01 — Crop-меню закрывает страницу
Диалог/меню обрезки полей должен позволять видеть верх, края и достаточную площадь самой страницы во время настройки. Сейчас overlay мешает визуально оценивать результат. Сделать адаптивный layout, особенно landscape: контролы не должны перекрывать критическую область предпросмотра.

### BUG-UI-CROP-02 — live preview обрезки
Изменения верх/низ/лево/право, симметричная обрезка и Auto должны сразу и предсказуемо отражаться на видимой странице. Пользователь должен понимать, какую часть изображения он отрезает до нажатия `Готово`.

### BUG-UI-INSETS-01 — Reader layout / system insets
Проверить status/navigation bars, landscape и edge-to-edge. Контент и chrome должны использовать согласованную геометрию viewport и не создавать лишние перекрытия/пустые зоны.

### BUG-UI-THEME-01 — тема Reader не должна меняться побочно
Смена режима чтения, повторное открытие книги и repagination не должны самопроизвольно менять выбранную тему/пресет.

## Library UI

### BUG-LIB-01 — badges форматов/прогресса
Проверить бейдж формата и процент на карточках: формат должен определяться корректно, а процент совпадать с фактическим сохранённым прогрессом Reader.

### BUG-LIB-02 — прогресс после возврата из Reader
После выхода из книги библиотека должна сразу показывать актуальный прогресс, без ложных `0%`/`100%` и без необходимости повторного запуска приложения.

## Candidate

### BUG-EPUB-ANIM-01 — анимация перелистывания EPUB
После стабилизации pagination/position отдельно проверить анимацию смены страниц EPUB. Не исправлять визуальную анимацию ценой изменения расчёта позиции или количества страниц.

# Порядок работы

1. Сначала исправить общий pipeline: `ReaderPosition / restore → pagination → totalPages → progress → mode switching`.
2. Затем EPUB как базовый формат.
3. После EPUB последовательно: MOBI → FB2 → TXT/archive → RTF → DOCX → Markdown.
4. После стабилизации текстового ридера — Chrome/Crop/Insets/Theme и Library UI.
5. После каждого общего исправления повторно прогнать уже проверенные форматы.
6. Не исправлять общий дефект отдельным format-specific hack, если первопричина находится в Reader/WebView/progress pipeline.

## Обязательная тестовая матрица для каждого текстового формата

- `Pages → Vertical`
- `Vertical → Pages`
- `Reader → Library → Reader`
- начало документа
- середина документа
- реальный конец документа
- `currentPage / totalPages`
- процент прогресса
- slider
- сохранение/восстановление позиции
- chrome
- тема/пресет
- сноски и внутренние ссылки, если формат их поддерживает
- `100%` только при достижении реального конца

## Definition of Done

Для каждого исправленного бага:

- найдена и описана первопричина;
- перечислены затронутые файлы;
- добавлен или обновлён regression test;
- проект успешно собирается;
- проблема проверена на реальном проблемном документе;
- повторно проверены связанные форматы/режимы;
- зелёные unit tests сами по себе не являются основанием закрывать баг.
