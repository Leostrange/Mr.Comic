# Анализ ошибок и багов ридера Mr.Comic (текстовый ридер)

Дата: 2026-07-17
Метод: ревью кода `feature-reader` / `engine-formats` + сверка с багрепортами
(`plans/006-text-page-reader-regressions.md`, `READER_MASTER_BACKLOG.md`,
`test-reports/text-reader-tasklist-2026-07-13.md`).

---

## 1. Резюме

Основной кластер проблем — **страничный режим (PAGE)**: ручное разрезание HTML на
страницы даёт нестабильную высоту, обрезание и пропуски; смена темы перезагружает
документ (белый экран); позиция хранится как номер страницы, а не текстовый якорь.
WEBTOON-режим работает лучше, но имеет O(N²)-пересборку документа при подгрузке.

Найдено: **3 бага уровня P0**, **7 уровня P1**, **4 уровня P2** + подтверждение
причин почти всех пользовательских симптомов из багрепортов.

## 2. P0 — критические баги

### P0-1. TextPaginator не разбивает крупные блоки
`engine-formats/.../text/pagination/TextPaginator.kt:62-71`
Цикл идёт по блокам (абзацам). Если один `<p>` длиннее `charsPerPage`, он целиком
попадает на одну страницу — WebView показывает только начало, остальное недоступно.
**Симптомы:** «пропуск страниц», «текст обрезается снизу».
**Фикс:** рекурсивное разбиение блока по границам предложений/строк, либо переход
на CSS multi-column пагинацию (см. §5.1).

### P0-2. Смена пресета/темы перезагружает документ
`feature-reader/.../ReaderScreen.kt:721`
`LaunchedEffect(reloadKey)` обнуляет `pageSource` и вызывает полный `loadUrl` при
любой смене цвета фона/текста.
**Симптом:** белый/пустой экран на несколько секунд при смене темы (TR-022, UI-002).
**Фикс:** цвета не входят в layout-fingerprint (это уже сделано в
`ReaderTextLayoutFingerprint`) — применять их через
`evaluateJavascript` патчем CSS-переменных `:root`, без перезагрузки. Держать
старый кадр до готовности нового.

### P0-3. O(N²)-пересборка документа в вертикальной ленте
`feature-reader/.../TextWebtoonSessionController.kt:54`
При каждой подгрузке пачки из 12 страниц весь HTML-документ пересобирается с нуля
и заново пушится в WebView.
**Симптомы:** медленное открытие длинных книг и архивов, лаги, вспышки.
**Фикс:** инкрементальная доставка через JS-мост (`appendPages(html)`), документ
загружается один раз как оболочка.

## 3. P1 — серьёзные баги

### P1-1. Принудительный разрыв слов через CSS
`TextPaginator.kt:117` — `word-wrap:break-word; overflow-wrap:break-word` в
обёртке страницы заставляет движок рвать слова в произвольном месте.
**Симптом:** «слова режутся на слоги без переноса». Базовый CSS ридера уже
починен (TR-005, 2026-07-15), но обёртка страниц в пагинаторе всё ещё
содержит эти свойства — симптом может возвращаться именно в PAGE-режиме.
**Фикс:** убрать из `wrapPage`, использовать `hyphens:auto` + `lang`-атрибут.

### P1-2. Потеря привязки секции при слиянии заголовка
`DocumentTextPaginator.kt:53` — при слиянии короткой секции-заголовка со следующей
всем страницам присваивается `sectionIndex` следующей секции.
**Симптом:** переход по TOC на «слитую» главу не находит страницу.
**Фикс:** хранить диапазон исходных секций (`firstSectionIndex..lastSectionIndex`).

### P1-3. «Плавающий» total страниц у EPUB
`EpubProgressCalculator.kt:40-51` — `total = visitedTotal + avg * unvisited`;
среднее меняется по мере чтения, total прыгает.
**Симптомы:** слайдер теряет позицию, прогресс скачет, ложный 100% на короткой
книге. Связан с PAG-001/TR-001 (частично закрыт, но эстимейтор остался).
**Фикс:** взвешивать непосещённые секции по размеру в байтах, а не по среднему
числу страниц; UI помечать total как «≈» до финальной пагинации.

### P1-4. Нет mutex на смену документа/пагинацию
`TextReaderOrchestrator.kt:162` — `paginationJob.cancel()` без `join()`;
параллельный `syncBookEngineTextLayer` может перезаписать `activeSession`.
**Симптомы:** гонки при быстрых свайпах, дубли/пропуски на границах секций,
«Empty HTML», артефакты при смене книги во время подсчёта (PAG-002).
**Фикс:** `Mutex` вокруг операций open/paginate/switch + `cancelAndJoin`;
привязывать все фоновые job к `comicId` и отбрасывать stale-результаты.

### P1-5. Выделение текста при свайпе
`ReaderScreen.kt:319, 351` — блокировка `selectstart` не срабатывает в
вертикальном режиме и при быстром свайпе.
**Симптом:** TR-010 / PAG-009.
**Фикс:** на время жеста выключать `user-select: none` через CSS-класс на body,
возвращать после завершения; long-press оставить как есть.

### P1-6. Вертикальная лента игнорирует status bar inset
`ReaderScreen.kt:1186` — при скрытом chrome `topPaddingPx` не учитывает системные
инсеты в scroll-режиме.
**Симптом:** текст под status bar (TR-011 / PAG-010).
**Фикс:** добавлять `WindowInsets.statusBars` в top padding для webtoon-режима.

### P1-7. Переключение режимов идёт по номеру страницы
`ReaderViewModel.kt:256` — `pendingScrollToAnchor` используется только для TOC;
режимы Страницы ↔ Лента обмениваются позицией через номер страницы.
**Симптом:** потеря точной позиции при переключении (PAG-007 / TR-008).
**Фикс:** при переключении вычислять ближайший видимый текстовый якорь и
восстанавливать по нему (единый ReadingLocator, см. §5.2).

## 4. P2 — заметные, но менее срочные

| # | Где | Суть | Симптом |
|---|-----|------|---------|
| P2-1 | `TextPaginator.kt:63` | Длина текста считается по сырому HTML — entity `&#1090;` = 7 символов вместо 1 | Нестабильная высота страниц, полупустые страницы на текстах с entity (кириллица!). Возможная причина «цифры вместо буквы»: обрезание HTML посреди entity при разрезании блока |
| P2-2 | `EpubProgressCalculator.kt:59` | `current.coerceAtMost(total)` маскирует ошибки эстимейтора | Прогресс «залипает» на 100% в конце |
| P2-3 | `ReaderViewModel.kt:700` | `initialPages = 1` для форматов с отложенным подсчётом | 1/1 = 100% до завершения пагинации (частично закрыто в LIB-001 на уровне модели, но UI-путь остаётся) |
| P2-4 | `ReaderScreen.kt:447` | Сноска извлекается как `innerText` с лимитом 3000 символов, без структуры | Длинная сноска обрезана/теряет вёрстку (NOTE-003/NOW-1) |

Отдельно: `TextWebtoonDocumentBuilder.kt:16` и JS-шаблоны в `ReaderScreen` вставляют
строки (`fontFamily`, body) в JS/HTML без экранирования — риск крэшей WebView на
книгах с «неудобными» символами. Рекомендуется общий helper `jsEscape()/htmlEscape()`.

## 5. Что улучшить (архитектура)

### 5.1. Пагинация: перейти с ручного разрезания HTML на CSS columns
Ручной эстимейтор по количеству символов принципиально не может дать точную
раскладку (шрифты, entity, картинки, таблицы). Надёжный путь:
`column-width:100vw; height:100vh` в WebView + JS-замер фактического числа
колонок. Это разом закрывает PAG-003 (обрезание), PAG-004 (полупустые страницы)
и большую часть PAG-002. Ручной пагинатор оставить только как fallback-оценку
total до первого рендера.

Минимальный промежуточный шаг, если columns — слишком большой рефакторинг:
JS-валидация после рендера (`scrollHeight > viewport` → переразбить страницу).

### 5.2. Единый ReadingLocator вместо номера страницы
Хранить позицию как `{sectionIndex, textAnchor/charOffset, progression}`.
Номер страницы — производная величина от текущего fingerprint раскладки.
Это закрывает: потерю позиции при смене шрифта/ориентации/режима (PAG-007),
расхождение слайдера и заголовка, и делает прогресс стабильным.

### 5.3. Инкрементальная гидратация WebView
Один `loadData` с оболочкой (CSS + JS-мост), дальше только
`evaluateJavascript`: `appendPages()`, `applyTheme()`, `setInsets()`.
Закрывает P0-2, P0-3 и «пустые кадры» при любых изменениях.

### 5.4. Декомпозиция монолитов (уже в бэклоге ARC-001..005 — подтверждаю приоритет)
`ReaderViewModel` ~4.7k строк, `ReaderScreen` ~6.2k, `EpubFormatReader` ~3.2k.
Пока они не разделены, каждый фикс несёт риск регрессии. Порядок из бэклога
правильный: сначала characterization-тесты (ARC-001d/e/f не закрыты), потом
вынос `ReaderSessionCoordinator` (закроет и P1-4).

### 5.5. Аудит runCatching (OPS-001) — поднять приоритет
423 использования `runCatching` в кодовой базе; уже подтверждён кейс, когда
ошибка `getPageCount()` молча подменялась предварительным значением (TR-001).
Такие «мнимые успехи» — источник самых трудноуловимых багов (ложный total,
ложный прогресс). Правило: fallback разрешён только с логом и явным статусом
degraded в состоянии.

### 5.6. Оракул целостности текста (PAG-008/TR-009) — сделать до дальнейших фиксов пагинации
Автотест «собери текст всех визуальных страниц и сравни с нормализованным
исходником» дешевле любого ручного QA и ловит сразу: потерю, дубль,
перестановку, внедрение тел сносок и «цифру вместо буквы». Без него каждый фикс
пагинации проверяется вручную по матрице форматов.

## 6. Сопоставление симптомов с причинами

| Симптом из багрепорта | Найденная причина |
|---|---|
| Пропуск страниц | P0-1 (неразбитые блоки) + P1-4 (гонки) |
| Обрезание текста сверху/снизу | P0-1 + эстимейтор по символам (P2-1); резерв панелей частично починен 2026-07-15 |
| Полупустые страницы | P2-1 (entity в подсчёте длины); компактор 30–65% — обходной путь, не причина |
| Слова режутся на слоги | P1-1 (break-word в wrapPage) |
| Цифра вместо буквы | Вероятно P2-1: разрез HTML внутри numeric entity (`&#1090;` → видимый «хвост» с цифрами). Нужен точечный тест |
| Ложный 100% у новой книги | P1-3 + P2-3 (модельная часть закрыта, UI-путь и эстимейтор — нет) |
| Белый экран при смене темы | P0-2 |
| Выделение при свайпе | P1-5 |
| Текст под status bar | P1-6 |
| Потеря позиции при смене режима | P1-7 |
| Медленные архивы | P0-3 + отсутствие кэша секций (FMT-003; cold open 10.4 с, getPageCount 8.9 с по замерам QA) |
| Popup сноски не вмещается | P2-4 + политика высоты (NOW-1 в работе) |
| TOC-переход мимо главы | P1-2 |

## 7. Рекомендуемый порядок работ

1. **Сначала измеримость:** оракул целостности (5.6) + структурированная
   диагностика (OPS-002). Иначе фиксы пагинации не верифицируемы.
2. **P0-2 (тема без перезагрузки)** — самый заметный пользователю фикс при
   минимальном объёме: цвета уже вне fingerprint, остался JS-патч.
3. **P1-4 (mutex/cancelAndJoin)** — устраняет целый класс «плавающих» багов
   границ секций до того, как чинить сами границы.
4. **P0-1 + P1-1 + P2-1 (пагинатор)** — вместе, одним заходом, с оракулом.
5. **P1-3 + P2-3 (total/прогресс)**, затем **P1-5/P1-6/P1-7** (жесты, insets, locator).
6. **P0-3 (webtoon append)** и архивы (FMT-003).
7. Параллельно малыми шагами — ARC-декомпозиция под characterization-тестами.
