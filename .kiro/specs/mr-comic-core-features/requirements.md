# Требования к приложению Mr.Comic

## Введение

Mr.Comic — современное Android-приложение для чтения, организации и перевода комиксов с богатой системой настроек, кастомизации интерфейса, синхронизацией и локальными AI-функциями (OCR и перевод). Приложение разрабатывается на Kotlin с использованием Jetpack Compose и Material3, без привязки к внешним ридерам.

## Требования

### Требование 1: Управление библиотекой комиксов

**User Story:** Как пользователь, я хочу организовывать свою коллекцию комиксов в библиотеке, чтобы легко находить и управлять своим контентом.

#### Acceptance Criteria

1. WHEN пользователь открывает приложение THEN система SHALL отобразить главный экран библиотеки с коллекцией комиксов
2. WHEN пользователь добавляет директорию THEN система SHALL просканировать её и добавить найденные комиксы в библиотеку
3. WHEN пользователь удаляет комикс из библиотеки THEN система SHALL удалить его только из базы данных AND NOT удалять файл с устройства
4. WHEN пользователь выбирает режим отображения (Сетка/Список/Папки) THEN система SHALL мгновенно переключить режим без задержек
5. WHEN пользователь использует поиск THEN система SHALL фильтровать результаты без влияния на производительность UI
6. IF пользователь нажимает на кнопку поиска повторно THEN система SHALL свернуть панель поиска

### Требование 2: Сканирование и индексация файлов

**User Story:** Как пользователь, я хочу автоматически индексировать комиксы из выбранных папок, чтобы не добавлять каждый файл вручную.

#### Acceptance Criteria

1. WHEN система сканирует директорию THEN она SHALL поддерживать форматы .cbz, .zip, .cbr, .rar, .pdf и папки с изображениями (.jpg, .png)
2. WHEN пользователь настраивает включение форматов THEN система SHALL предоставить опции: Всегда / Только если есть в папке / Никогда
3. WHEN индексация запущена THEN система SHALL выполнять её в фоне через WorkManager без блокировки UI
4. WHEN система находит комикс THEN она SHALL извлечь и закэшировать обложку для быстрого отображения
5. WHEN приложение перезапускается во время индексации THEN система SHALL восстановить процесс индексации
6. WHEN индексация выполняется THEN система SHALL отображать прогресс и статус сканирования

### Требование 3: Чтение комиксов

**User Story:** Как читатель, я хочу комфортно читать комиксы с плавной навигацией и масштабированием, чтобы наслаждаться контентом.

#### Acceptance Criteria

1. WHEN пользователь открывает комикс THEN система SHALL отобразить его в полноэкранном режиме со скрытыми тулбарами
2. WHEN пользователь делает тап по странице THEN система SHALL показать индикатор "страница X/Y" в правом нижнем углу
3. WHEN пользователь делает двойной тап THEN система SHALL циклически переключать масштаб: по ширине → по высоте → по экрану
4. WHEN пользователь свайпает страницу THEN система SHALL плавно перелистывать без задержек
5. WHEN система отображает страницу THEN она SHALL предзагрузить соседние страницы (±2) для быстрого перелистывания
6. WHEN пользователь закрепляет страницу (Pin) THEN система SHALL сохранить это состояние между сессиями

### Требование 4: Панели управления и жесты

**User Story:** Как пользователь, я хочу быстро получать доступ к настройкам во время чтения, чтобы не прерывать процесс.

#### Acceptance Criteria

1. WHEN пользователь делает долгий тап по центру THEN система SHALL показать верхнюю полупрозрачную панель настроек (scrim 8-16%)
2. WHEN пользователь делает долгий тап слева/справа THEN система SHALL показать боковые панели с быстрыми настройками
3. WHEN пользователь открывает нижнюю панель THEN система SHALL отобразить миниатюры страниц с горизонтальным скроллом
4. WHEN пользователь настраивает зоны тапов THEN система SHALL применить настройки чувствительности и ограничения зон
5. WHEN панели отображаются THEN они SHALL NOT мерцать AND NOT перекрывать активные зоны
6. WHEN миниатюры загружаются THEN система SHALL использовать lazy-подгрузку для плавной работы

### Требование 5: Настройки чтения

**User Story:** Как пользователь, я хочу настраивать параметры чтения под свои предпочтения, чтобы читать было максимально комфортно.

#### Acceptance Criteria

1. WHEN пользователь изменяет ориентацию THEN система SHALL поддерживать режимы: портрет, альбом, авто
2. WHEN пользователь выбирает режим чтения THEN система SHALL переключать между постраничным и вертикальной лентой
3. WHEN пользователь настраивает эффект перехода THEN система SHALL применить выбранную анимацию и скорость
4. WHEN система обнаруживает двойной разворот THEN она SHALL автоматически определить и отобразить его корректно
5. WHEN пользователь включает режим манги THEN система SHALL переключить направление чтения справа-налево
6. WHEN пользователь настраивает локальную яркость THEN система SHALL применить её только для ридера
7. WHEN пользователь изменяет параметры THEN система SHALL применить их без перезапуска ридера
8. WHEN сессия чтения завершается THEN система SHALL сохранить все настройки в ReadingSession/Settings

### Требование 6: Навигация по страницам

**User Story:** Как читатель, я хочу быстро переходить к нужной странице, чтобы не листать весь комикс.

#### Acceptance Criteria

1. WHEN пользователь открывает панель миниатюр THEN система SHALL отобразить все страницы с горизонтальным скроллом
2. WHEN пользователь просматривает миниатюры THEN система SHALL подсветить текущую страницу
3. WHEN пользователь удерживает миниатюру THEN система SHALL показать предпросмотр страницы
4. WHEN пользователь тапает по миниатюре THEN система SHALL мгновенно перейти к выбранной странице
5. IF комикс содержит 500+ страниц THEN система SHALL обеспечить плавную работу без заметных лагов

### Требование 7: Кастомизация интерфейса

**User Story:** Как пользователь, я хочу настраивать внешний вид приложения под свой вкус, чтобы интерфейс был приятным для меня.

#### Acceptance Criteria

1. WHEN пользователь выбирает тему THEN система SHALL предоставить опции: Системная, Светлая, Тёмная, Пользовательская
2. WHEN пользователь настраивает полупрозрачность THEN система SHALL применить альфа-канал к панелям (scrim)
3. WHEN пользователь включает blur THEN система SHALL применить эффект размытия к панелям
4. WHEN пользователь переключает тему THEN система SHALL применить её без перезапуска приложения
5. WHEN пользователь открывает редактор оформления THEN система SHALL предоставить настройки цветов (primary/secondary/background/overlay alpha)
6. WHEN пользователь настраивает шрифты THEN система SHALL применить выбранное семейство и размеры для меню/оверлеев/индикаторов
7. WHEN пользователь настраивает UI-элементы THEN система SHALL применить пакеты иконок, радиусы, тени, отступы
8. WHEN пользователь сохраняет пресет THEN система SHALL сохранить все настройки для повторного использования
9. WHEN пользователь сбрасывает настройки THEN система SHALL восстановить дефолтные значения

### Требование 8: Синхронизация данных

**User Story:** Как пользователь с несколькими устройствами, я хочу синхронизировать свой прогресс и настройки, чтобы продолжать чтение на любом устройстве.

#### Acceptance Criteria

1. WHEN пользователь добавляет облачный провайдер THEN система SHALL предоставить экран "Личные папки" с кнопкой "+"
2. WHEN пользователь настраивает синхронизацию THEN система SHALL предоставить опции: что синхронизировать (прогресс, закладки, настройки)
3. WHEN пользователь настраивает периодичность THEN система SHALL выполнять синхронизацию согласно расписанию
4. WHEN пользователь включает "только Wi-Fi" THEN система SHALL синхронизировать только при подключении к Wi-Fi
5. WHEN возникает конфликт данных THEN система SHALL разрешить его согласно выбранной политике
6. WHEN синхронизация выполняется THEN она SHALL работать в фоне без блокировки UI
7. WHEN пользователь запускает ручную синхронизацию THEN система SHALL выполнить её без ошибок

### Требование 9: Распознавание текста (OCR)

**User Story:** Как читатель иностранных комиксов, я хочу распознавать текст на страницах, чтобы затем переводить его.

#### Acceptance Criteria

1. WHEN пользователь включает OCR THEN система SHALL использовать ML Kit или Tesseract для распознавания
2. WHEN система распознаёт текст THEN она SHALL поддерживать языки: RU, EN, FR
3. WHEN OCR обрабатывает страницу THEN система SHALL получить координаты блоков, строк и слов
4. WHEN пользователь включает/выключает OCR THEN система SHALL предоставить переключатель в настройках
5. WHEN OCR корректно работает THEN он SHALL выделять текстовые блоки на тестовых страницах
6. IF возникает ошибка распознавания THEN система SHALL залоггировать её AND NOT вызвать краш приложения

### Требование 10: Перевод текста

**User Story:** Как читатель иностранных комиксов, я хочу переводить распознанный текст на свой язык, чтобы понимать содержание.

#### Acceptance Criteria

1. WHEN пользователь настраивает перевод THEN система SHALL поддерживать локальные модели (ONNX/MarianMT) и облачные API
2. WHEN пользователь выбирает приоритет THEN система SHALL использовать локальный перевод с fallback на облако
3. WHEN система переводит текст THEN она SHALL поддерживать направления: RU, EN, FR (все комбинации)
4. WHEN перевод выполняется THEN система SHALL кэшировать результаты для повторного использования
5. WHEN пользователь запускает перевод из ридера THEN система SHALL вернуть результат менее чем за 2 секунды (локально — по возможности)
6. WHEN пользователь переключает провайдера THEN система SHALL применить изменения без перезапуска

### Требование 11: Визуализация перевода

**User Story:** Как читатель, я хочу видеть перевод поверх оригинального текста, чтобы не переключаться между экранами.

#### Acceptance Criteria

1. WHEN система отображает перевод THEN она SHALL рендерить текст поверх исходного изображения с сохранением геометрии
2. WHEN пользователь настраивает подложку THEN система SHALL применить выбранный цвет и прозрачность
3. WHEN пользователь настраивает шрифт THEN система SHALL применить выбранный размер к тексту перевода
4. WHEN пользователь нажимает "Перевести страницу" THEN система SHALL выполнить OCR и перевод текущей страницы
5. WHEN пользователь включает "Авто-перевод" THEN система SHALL автоматически переводить страницы при перелистывании
6. WHEN система кэширует перевод THEN она SHALL использовать ключ: comicId+pageIndex+hash(settings)
7. WHEN перевод отображается THEN текст SHALL быть читаемым AND NOT перекрывать критичные элементы
8. WHEN авто-перевод работает THEN он SHALL NOT снижать FPS более чем на 50% от baseline

### Требование 12: Сохранение состояния

**User Story:** Как пользователь, я хочу продолжать чтение с того места, где остановился, чтобы не искать нужную страницу.

#### Acceptance Criteria

1. WHEN пользователь закрывает комикс THEN система SHALL автоматически сохранить текущую страницу и настройки
2. WHEN пользователь открывает комикс повторно THEN система SHALL восстановить последнюю прочитанную страницу
3. WHEN пользователь открывает комикс повторно THEN система SHALL восстановить режим чтения и настройки
4. WHEN система сохраняет настройки THEN она SHALL резервировать важные параметры в DataStore
5. WHEN приложение перезапускается THEN система SHALL восстановить состояние без потери данных

### Требование 13: Производительность и стабильность

**User Story:** Как пользователь, я хочу, чтобы приложение работало плавно и стабильно, чтобы чтение было комфортным.

#### Acceptance Criteria

1. WHEN пользователь свайпает/зумирует страницы THEN система SHALL обеспечить плавность на разных устройствах
2. WHEN OCR/перевод работают THEN система SHALL сохранять стабильность даже при низком FPS
3. WHEN приложение работает на устройстве с вырезом THEN панели SHALL корректно отображаться без перекрытия
4. WHEN выполняются тесты производительности THEN система SHALL предоставить метрики кадра
5. WHEN проводится тестирование THEN все smoke и regression тесты SHALL пройти успешно

### Требование 14: Документация и локализация

**User Story:** Как разработчик/пользователь, я хочу иметь документацию и поддержку нескольких языков, чтобы легко работать с приложением.

#### Acceptance Criteria

1. WHEN проект завершён THEN система SHALL содержать README.md с описанием проекта
2. WHEN проект завершён THEN система SHALL содержать ARCHITECTURE.md с описанием архитектуры
3. WHEN проект завершён THEN система SHALL содержать документацию модулей, API и ключей DataStore
4. WHEN приложение запускается THEN оно SHALL поддерживать локализацию: RU, EN, FR
5. WHEN пользователь выбирает язык THEN все строки интерфейса SHALL отображаться на выбранном языке
